# 새 세션 목표: 목업 기반 pok-ui 재구축

## 목표

기존 검토 목업과 사용자의 후속 수정 요구를 기준으로 pok-ui의 화면·편집 흐름·PoB 실행 구조를 재구축한다. PoK·AI 없이 원본 PoB의 수동 빌드 작업을 수행하는, 빠르고 실제 사용 가능한 데스크톱 작업 공간을 만든다. XML 보존·저장/복원·undo/redo·revision 안전성에서 검증된 기반을 재사용하고, 교체 후 사용하지 않는 화면·상태·API·어댑터·의존성·테스트·문서를 정리한다. PoK는 이후 연결 가능한 선택 기능으로 유지한다.

이 문서는 새 goal과 새 세션의 실행 지시안이다. 이 문서 작성만으로 기존 paused goal을 재개하거나 제품 구현을 시작하지 않는다. 새 세션에서 사용자가 이 목표의 실행을 지시하면 아래 순서로 진행한다. 전체 기능 동등성이 미완료인 상태를 1단계 완료와 혼동하지 않는다.

## 기준 자료와 우선순위

1. 현재 사용자 지시와 이 문서.
2. `artifacts/ui-redesign/pok-workspace-review.html`: 실제 열어 조작하고 화면을 확인할 UI 기준.
3. `docs/UI-REDESIGN-20261103.md`: 목업 이후 사용자 수정 요구와 편집/계산 동작 기준.
4. `docs/POB-RUNTIME-PERFORMANCE-20261103.md`: 실제 측정·현재 병목과 개선 순서.
5. `AGENTS.md`, `docs/ARCHITECTURE.md`, `docs/VALIDATION.md`, `docs/CURRENT-PLAN.md`, `docs/HANDOFF-20261030.md`: 경계·보존 대상·실행 이력.

새 화면은 기존 제품 화면의 작은 수정이 아니라 이 목업을 기반으로 구현한다. 목업의 가상 수치·대기 시간·아이템/옵션·트리 좌표를 제품 데이터나 게임 규칙으로 이식하지 않는다. 목업에 없는 동작은 원본 PoB의 실제 기능과 기존 계약을 확인해 연결한다. 사용자의 확정된 개별 요구와 아직 검토 중이던 세부사항을 구분한다.

## 반드시 반영할 화면·작업 흐름

- 좌측 작업 목록: 장비/스킬/패시브/전투 조건/계산/비교/파티/노트, 하단 설정. PoK/AI는 선택 보조 영역.
- 상단 같은 줄: 빌드 선택·저장·다른 이름으로 저장·Import/Export Build·인접한 undo/redo. 우측에 일반/무기 I/무기 II/전직 패시브 현황과 편집 가능한 레벨·직업.
- 장비 3분할: 좌측 상단 인게임 슬롯 배치, 좌측 하단 보유 목록과 목록 조작, 우측 생성·옵션 편집. 장비/패시브 주얼 탭을 전환해도 보유 목록은 유지한다.
- 전면 장비 전환은 무기 I/II로 표현한다. 맵핑/보스 구분을 만들지 않는다. 기존 XML의 inactive item set은 보존하고 별도 관리 흐름을 제공한다.
- Create Item에서 유형/희귀도를 선택하고 고유 검색 또는 희귀 베이스 선택으로 연결한다. 실제 원본 메타데이터에 따라 옵션을 조절한다. 숫자는 직접 입력과 값 옆 +/− 버튼을 제공한다.
- 모든 장착/보유 아이템 hover/focus에서 옵션을 보여준다. 주얼은 해당 소켓의 실제 트리 위치 미니맵과 옵션을 함께 보여준다. 선택 슬롯은 테두리로 표현한다.
- 유효한 일반 편집은 별도 적용/저장 없이 반영·재계산한다. 미완성 입력은 유지하며 오류를 필드에 표시한다. 파일 저장·복구용 자동 보존·편집 반영을 구분한다. 생성/what-if 초안과 AI 제안은 명시 적용 전까지 원본과 분리한다.
- 장비/스킬 등에서 우측 요약을 유지하고 계산 대상·revision·갱신 상태를 표시한다. 계산 화면은 목업처럼 동시 표시하는 고밀도 패널로 구성하고 중복 요약 공간을 통합한다.
- 계산값 hover/focus에 원본 PoB가 제공한 기여·배율·조건·출처를 보여주고 관련 슬롯/그룹/노드/조건으로 이동·강조한다. 근거가 없는 항목은 가용성/미지원 상태를 표시한다.
- 일반 작업에서 XML·JSON·DTO 해석을 요구하지 않는다. 원문/로그/manifest는 명시적으로 여는 진단/고급 도구에 보존한다. 미지원 입력 줄을 조용히 버리지 않는다.

## 실행 구조와 책임 경계

- 원본 PoB 계산·편집 API를 사용하는 독립 runtime을 유지한다. 렌더러에 게임 규칙이나 근사 계산을 복제하지 않는다. 공유 PoK 저장소와 원본 PoB 소스를 수정하지 않는다.
- PoB 프로세스를 지속 실행한다. 먼저 요청별 XML 복원을 유지해 초기화 비용을 제거하고, 추가 상태 재사용은 오염 회귀를 확인한 뒤 도입한다.
- 전체 파일 검증을 매 조작마다 반복하지 않도록 시작/준비/교체 검증·검증 결과 재사용·변경 감지 정책을 정한다. 출처 검사를 우회하지 않는다.
- 최신 입력 우선으로 대기 중인 오래된 계산/조회와 중복 요청을 대체한다. 편집/계산/요약 응답을 묶고 느린 상세 조회가 최신 요약을 막지 않게 한다.
- crash/timeout/cancel은 명확히 구분하고 필요한 경우 runtime을 폐기·재시작한다. 늦은 결과를 다른 build/revision/runtime에 적용하지 않는다.
- 검증된 고정 번들을 기본으로 유지하되 설치 PoB 연결과 버전별 capability 검사를 설계한다. 버전 전환 시 프로세스·카탈로그·캐시를 폐기한다. 버전 문자열만으로 호환 판정을 끝내지 않는다. PoK 연결 시 양쪽 PoB 출처 호환성을 별도 검사한다.

## 보존·정리 원칙

- 시작 시 작업 브랜치/dirty 상태를 확인하고 기존 27차 미커밋 작업과 목업/문서를 별도로 식별·보존한다. main에 직접 커밋하거나 기존 변경을 일괄 폐기하지 않는다.
- 원본 XML과 unknown/inactive 데이터, 원본 파일 보호, 저장/복원, undo/redo, 계산의 입력 귀속을 보존한다. 기존 안전성 테스트는 재사용하되 새 구조에 맞게 갱신한다.
- 화면 전환 시 기능별로 구화면→신화면 연결표를 만든다. 대체 흐름 검증 후 구컴포넌트·CSS·hook·중복 상태·죽은 IPC/계약·어댑터·스크립트·패키지 의존성을 제거한다. dynamic import/등록 테이블/배포 경로도 검사한다.
- 화면을 삭제해 기존 기능을 미지원으로 숨기지 않는다. 기능 목록에 구현/검증/미지원 상태를 남기고 제품에 필요한 기능을 신화면으로 연결한다. PoK 미접속을 이유로 선택 연동 코드를 무조건 삭제하지 않는다.
- 테스트는 새 사용자 동선과 실제 안전성을 검증하도록 갱신한다. 구화면 selector만 검사하는 테스트는 대체 후 제거하되 실패를 감추려고 테스트를 삭제하지 않는다. 임시 진단/개인 데이터는 fixture나 배포물에 넣지 않는다.
- 문서의 과거 성공 결과를 현재 구현의 검증으로 사용하지 않는다. 현행 설명은 갱신하고 과거 기록은 이력임을 분명히 한다.

## 작업 순서

1. 현재 상태 보존·기능/호출 경로/정리 대상 감사. 목업을 직접 확인하고 실제 입력/클릭→반영 시간 계측을 준비한다.
2. 지속 runtime·검증 캐시·최신 입력 요청 처리를 구현한다. 원본 복원·실패/취소/what-if 격리와 revision 회귀를 확인한다.
3. 목업의 전역 셸과 장비 화면을 실제 데이터로 완결한다. 가져오기→장착/옵션/무기 전환→자동 계산→우측 수치→undo/redo→저장/재시작/내보내기를 먼저 입증한다.
4. 같은 구조로 스킬/패시브/조건/고밀도 계산/비교/파티/노트/설정을 연결한다. hover 근거와 관련 위치 이동도 실제 원본 데이터로 검증한다. 구경로는 교체 단위로 정리한다.
5. 남은 PoB 기능 차이를 목록화해 연결하고, 설치 PoB 호환 흐름·선택 PoK 연결 경계를 확인한다. 최종 사용성/배포 검증과 불필요 코드 정리를 마무리한다.

## 완료 기준

- 목업과 후속 수정 요구를 실제 Electron 앱에 반영했다. 1920×1080/1024×768에서 핵심 조작·가독성·hover/키보드 접근·화면 잘림을 직접 확인한다.
- 지원되는 대표 합성 빌드로 새 계산이 성공한다. 장착/옵션/젬/트리/조건 변경과 무기 세트 전환이 수동 Calculate/Apply 없이 올바른 revision의 수치로 갱신된다.
- 빠른 연속 입력·빌드 전환·실패·취소·프로세스 종료·what-if 이후에도 원본/다음 계산/undo가 오염되지 않는다. 사용자 행동을 기준으로 undo를 묶는다.
- 저장/재시작 후 같은 작업 공간을 복원하고, 내보낸 XML을 실제 원본 PoB에서 열어 아이템·스킬·트리 편집을 확인한다. 개인 데이터 검증은 별도 보호된 작업 공간에서만 한다.
- 단순/대표/무거운 입력을 구분해 cold 시작, warm 조작→최종 수치, 대기열, 복원/계산, UI 반영 시간을 기록한다. 입력 시각 반응 100ms 이내를 목표로 하며 대표 warm 갱신의 수치 기준은 초기 실측으로 정하고 최종 결과와 비교한다. 과거 빈 빌드 0.33~0.38초는 앱 성능 보장이 아니다.
- `npm run check`, `npm run build`와 필요한 실제 Electron/Windows 패키지 동선을 통과한다. 수행하지 않은 모델/GUI/패키지 검증은 미수행으로 명시한다.
- 기능 연결표의 미지원/미검증 항목, 남은 구코드와 이유를 남긴다. 실제로 사용하지 않는 구경로·의존성·중복 구현을 정리했다. 장비 1단계 통과만으로 전체 PoB 동등성을 선언하지 않는다.
- 최종 UI 커밋, runtime/PoB 버전·출처, 실측 결과, 사용자 동선 결과, 미해결 제약을 기록한다. #188 해결 또는 재평가 준비 완료는 별도 근거 없이 선언하지 않는다.

## 새 세션에 전달할 시작 지시

> `docs/GOAL-UI-REBUILD-20261103.md`를 새 goal의 목표·범위·완료 기준으로 삼아 작업하라. `artifacts/ui-redesign/pok-workspace-review.html`을 직접 열어 확인하고 후속 사용자 요구를 반영한 UI를 구현하라. 기존 안전한 XML/저장/undo/revision 기반은 재사용하되 화면과 실행 흐름을 재구축하고, 대체 검증 후 불필요한 구코드를 정리하라. 기존 dirty 변경을 먼저 보존하고 PoK/원본 PoB 소스는 수정하지 마라. 지속 PoB runtime과 장비의 실제 자동 반영·재계산 동선을 먼저 완성한 뒤 나머지 작업 영역으로 확장하라. 테스트 개수나 목업 시연을 실제 사용성·성능 완료 근거로 대신하지 마라.
