# 수동 작업 공간 재설계 — 좌측 목록·상단 빌드 작업 확정, 상세 검토 중

사용자 E2E 피드백을 새 기준으로 삼는다. 원문/JSON 중심 화면, 잦은 적용·저장, 계산 대기, 접근하기 어려운 메뉴 때문에 현재 UI를 실제 작업에 쓰기 어렵다는 지적이다. 기존 기능 추가 목표는 사용자에 의해 일시 정지되었다. 이 문서는 구현 승인 요청용이며 기존 디자인을 승인 없이 대체하지 않는다.

목업: `artifacts/ui-redesign/pok-workspace-review.html`. 사용자가 좌측 작업 목록안을 선택했다. 빌드 선택·저장·다른 이름으로 저장·Import/Export Build는 원본 PoB처럼 상단 같은 줄에 노출한다. 장비 교체·필드 수정·젬 레벨 변경·계산 상세·관련 위치 이동·계산 지연/실패를 조작할 수 있다. 수치·계산 지연은 설계 시연용 가상 데이터다. 실제 PoB 계산이나 앱 성능을 검증한 목업이 아니다. 패시브 배치는 화면 구조를 설명하는 도식이며 실제 게임 트리가 아니다.

## 정보 구조

- 상단 전역: 빌드 선택 / 저장 / 다른 이름으로 저장 / Import/Export Build를 같은 줄에 고정한다. 되돌리기·다시 실행은 Import/Export Build 바로 옆에 붙인다. 상단 우측에는 패시브 할당/전직 포인트 현황과 편집 가능한 레벨·직업을 둔다. 설정은 좌측 사이드바 하단에 둔다. 핵심 파일 작업을 파일 드롭다운 안에 숨기지 않는다.
- 좌측 기본 작업: 장비 / 스킬 / 패시브 / 전투 조건 / 계산 / 비교 / 파티 / 노트. 설정은 사이드바 하단의 별도 항목이다. 작업 간 이동은 한 번에 가능해야 한다.
- 장비 작업 영역은 좌우로 나누고 좌측을 상하로 분할한다. 좌측 상단: PoE2 슬롯 배치형 장착 UI. 좌측 하단: 보유 아이템 목록·Sort/미사용 삭제/전체 삭제/삭제. 우측: Create Item·고유 조회·희귀 베이스 선택·아이템 옵션 편집. 전역 능력치 요약은 별도 우측 영역에 유지한다. 일반 보유 아이템 옵션 수정은 자동 반영하고, 생성 초안은 빌드에 추가 전까지 분리한다.
- 스킬: 그룹과 젬 목록, 레벨·퀄리티·효과·활성 상태를 직접 편집한다. 현재 편집 그룹과 계산 대상을 구분한다.
- 우측: 계산 대상과 현재 구성의 공격·방어·저항·자원·요구량을 모든 작업에서 유지한다. 수치에서 관련 계산 항목으로, 문제에서 관련 슬롯/젬/조건으로 바로 이동한다.
- 계산 상세: 사람이 읽는 명칭·수치·분해표와 관련 위치 링크를 사용한다. JSON을 화면 콘텐츠로 제시하지 않는다.
- PoK/AI: 기본 수동 편집과 분리된 선택 기능. 일반 탐색 공간을 차지하지 않도록 접힌 보조 영역에 둔다.
- XML·원문·엔진 로그·manifest는 명시적으로 연 고급 진단/내보내기 영역으로 옮긴다. 게임 아이템 붙여넣기 같은 원문 입력은 사용자가 선택한 가져오기 동선에만 둔다.

선택된 배치는 좌측 작업 목록이다. 상단 탭 대안은 현재 목업에서 제거했다. Import/Export Build는 상단 버튼으로 전용 화면을 열고 Import Build / Export Build를 전환한다. 좌측 작업 메뉴와 우측 수치 패널은 유지한다.

## 편집과 저장

유효한 숫자/선택/체크 변경은 수동 저장·적용 버튼 없이 반영한다. 텍스트·숫자 입력은 입력 중 상태를 보존하고 짧은 debounce 또는 Enter/포커스 이동으로 유효한 변경을 묶는다. 잘못되거나 미완성인 값은 해당 필드에 표시하고 마지막 유효한 상태를 보존한다.

필드 편집의 자동 반영·자동 계산과 파일 저장은 구분한다. 저장 버튼은 현재 파일을 명시적으로 저장하고, 다른 이름으로 저장은 새 파일로 저장한다. 파일 저장 전에는 변경 상태를 표시한다. 작업 복구용 자동 보존은 별도 상태로 표시하며 파일이 저장됐다고 오인하게 하지 않는다. 저장 대상이 정해지지 않았으면 최초 저장에서 대상을 선택한다. 원본을 사용자 동작 없이 덮어쓰지 않는다. XML 정본·unknown/inactive 보존을 유지하며 사용자 폼으로 전체 문서를 다시 만들지 않는다. undo는 계산 횟수 대신 사용자의 편집 단위를 기준으로 묶는다. AI 제안의 검토·명시 적용은 일반 수동 편집의 자동 반영과 구분한다.

## 계산 반응성 — 구현 전 확인할 핵심

이 문제는 레이아웃만 바꿔 해결할 수 없다. 현재 `src/main/pob-runtime.ts`의 요청 실행은 PoB 프로세스를 생성한다. 이것이 전체 지연 중 얼마나 차지하는지는 별도 프로파일링해야 한다.

승인 후 다음을 측정·개선한다.

1. 입력/장착 UI 피드백 목표 100ms 이내. 이는 목표이며 현재 측정 결과가 아니다.
2. 유효 변경을 짧게 묶어 자동 계산하고, 대기열은 최신 입력을 우선한다. 오래된 결과는 현재 결과로 표시하지 않는다.
3. 반복 프로세스 시작·데이터 초기화·계약/자원 검증·중복 inspection 비용을 분리해서 측정한다. 따뜻한 런타임/캐시를 검토하되 요청 간 상태 오염을 허용하지 않는다.
4. 원본 PoB의 계산을 계속 사용한다. 렌더러에 근사 게임 계산이나 별도 판단 규칙을 만들지 않는다. PoK 저장소는 동시에 수정하지 않는다.
5. 계산 중에는 이전 수치를 남기되 ‘이전 결과·갱신 중’으로 표시한다. 실패 시 이전 값과 실패 상태를 구분하고 재시도한다. 근거 없는 진행률 %를 만들지 않는다.
6. 빠른 대표 빌드와 무거운 빌드에서 cold/warm 계산 시간을 실제 측정한 뒤 성능 기준을 확정한다. 목업의 지연 시연을 성능 근거로 쓰지 않는다.

## 승인 후 검증할 사용자 작업

- 장비를 검색·한 번 장착 → 시각적으로 즉시 장착 상태 반영 → 별도 계산 버튼 없이 해당 입력의 우측 수치 갱신.
- 장착 아이템 수치/젬 레벨 수정 → 입력 포커스 유지 → 자동 반영·저장·계산 → undo/redo.
- 일반 편집에 원문·JSON·엔진 DTO 해석이나 반복 모달 확인이 필요하지 않음.
- 계산 상세에서 관련 슬롯/젬/패시브/조건으로 이동하고 대상을 강조.
- 빠른 연속 입력·계산 실패·취소·문서/세트 전환에서 현재 대상과 결과 소유권을 유지.
- 활성 구성과 계산 대상을 명확히 표시. 미측정 후보나 비활성 구성의 수치를 현재 측정처럼 보이지 않게 함.
- 1920×1080, 1024×768 실제 앱에서 주 작업·우측 수치·직접 메뉴 접근을 확인.
- 사용자 실사용 E2E로 조작 단계와 대기 시간을 확인. 테스트 개수나 API 호출 성공으로 사용성 승인을 대체하지 않음.

사용자 확정: 좌측 작업 목록, 상단 같은 줄의 빌드 선택·저장·다른 이름으로 저장·Import/Export Build. 상세 검토 대기: 정보 밀도, 자동 반영·계산 정책, 계산 상세 표현과 관련 위치 이동. 승인 전에는 제품 코드에 적용하지 않는다. 기존 27차 미커밋 변경은 보존하며 그 기능 검증도 자동 재개하지 않는다.

검토용 브라우저 확인: 장비 장착·필드/젬 수정의 자동 갱신, undo/redo, 계산 상세→관련 장비 이동, 실패 시 이전 값 구분과 재시도를 확인했다. 두 배치의 1920/1024 장비·스킬·계산 화면 및 좁은 화면에서 가로 잘림을 확인했다. 1024에서는 장착 버튼·우측 경고·상태줄이 화면 안에 있음을 점검했다. 이는 목업 동작 확인이며 실제 앱 사용성 승인·엔진 성능 검증을 대신하지 않는다.

사용자 선택 반영 후 재확인: 좌측 작업 목록만 남기고, 빌드 선택·저장·다른 이름으로 저장·Import/Export Build의 중심선이 1920/1024에서 같은 줄인지 확인했다. 저장 시 미저장 표시 해제, 다른 이름 저장 시 빌드 선택 이름 변경, Import/Export 전용 화면 전환을 목업에서 확인했다. 실제 파일 쓰기·계정 접근·제품 코드 변경은 수행하지 않았다.

추가 사용자 확정: 되돌리기/다시 실행을 Import/Export Build 인접 위치로 이동하고 설정은 좌측으로 이동한다. 헤더 우측 패시브 현황은 클릭하면 트리로 이동하며 레벨/직업은 직접 편집한다. 직업 변경의 연결 유지/초기화 여부와 실제 변경 노드는 원본 PoB가 판단한다. 목업의 선택 대화상자·포인트 값은 흐름 시연이며 게임 규칙을 구현한 것이 아니다.

## 사용자 제공 PoB 이미지 반영 — 장비 3분할

- 헤더의 일반 포인트 외에 무기 I/II 전용 포인트와 전직 포인트를 함께 표시한다. 무기 I/II는 색상뿐 아니라 이름으로도 구분한다. 실제 값/한도는 원본 PoB 데이터에서 받는다.
- 장착 UI는 무기·투구·보조 무기·목걸이·갑옷·반지·장갑·장화·허리띠·호신부·플라스크를 슬롯 위치와 크기로 표현한다. 필요한 추가 슬롯/패시브 주얼은 엔진이 제공하는 범위로 연결한다.
- 모든 실제 장착 아이템/보유 목록 행은 호버 및 키보드 포커스에서 옵션·요구량·장착/해제 비교를 제공한다. 빈 슬롯에는 아이템이 있다고 표시하지 않는다. 화면 가장자리에서 툴팁 위치를 보정한다.
- Create Item → 희귀도/유형/이름/베이스 선택. 고유는 필터·검색 가능한 Uniques 조회 도구로 이동하고, 희귀는 베이스를 선택해 편집 공간을 연다.
- 고유: 변형·퀄리티·소켓·룬과 옵션별 범위 조절. 희귀: 베이스 고정 속성·효과 선택·촉매·접두/접미·Add modifier·범위 조절. 성유/타락과 고급 텍스트 편집/비슷한 아이템 검색 진입점을 함께 둔다.
- 옵션의 개수·가능 여부·범위·미지원 판단은 실제 구현에서 원본 PoB의 동적 메타데이터와 API를 사용한다. 목업의 고정 옵션·예시 수치를 게임 규칙으로 구현하지 않는다.
- 새 아이템 초안은 Add to build 전까지 현재 구성에 반영하지 않는다. 기존 보유 아이템을 닫는 동작과 새 초안을 취소하는 동작을 구분한다. 삭제는 확인하고 undo할 수 있게 한다.
- 이미지 속 사용자의 빌드/보유 아이템 목록을 fixture로 옮기지 않고 별도 가상 아이템/수치로 구성했다. 제품 코드·실제 파일·엔진 저장소는 수정하지 않는다.

## 인게임 장비 배치·패시브 주얼 공존 추가 지시

- 장착 영역에서 맵핑/보스 장비 선택을 제거한다. 전면에는 무기 세트 I/II만 두고 무기 슬롯 표시를 전환한다. 기존 XML의 비활성 item set 데이터를 삭제하거나 임의로 합치는 지시는 아니다.
- 인게임 참고 이미지의 무기·투구·목걸이·갑옷·반지·장갑·허리띠·장화·플라스크/호신부 위치 관계를 반영한다. 선택은 슬롯 테두리만으로 알 수 있게 하고 하단의 ‘선택: 부위’ 문구를 제거한다.
- 좌측 상단 안에 장비 / 패시브 주얼 탭을 둔다. 탭을 바꿔도 좌측 하단 보유 목록과 우측 생성·편집 공간은 유지한다.
- 주얼 탭은 활성 트리의 소켓별 장착 목록을 보여준다. 소켓 hover/focus는 해당 소켓을 강조한 트리 위치 미니맵과 현재 주얼 옵션/비교를 하나의 팝오버에서 함께 제공한다. 빈 소켓도 위치를 확인할 수 있다.
- 위치와 소켓 목록은 구현 시 원본 PoB의 선택 트리·좌표·연결·소켓 ID를 사용한다. 목업의 미니맵은 위치 표시 방법의 예시이며 실제 게임 좌표·경로·노드 할당 판단이 아니다.

선택안 목업 확인: 1920/1024에서 장착 영역에 장비 세트(맵핑/보스) 선택과 선택 부위 문구가 없고, I/II 전환으로 무기 표시가 바뀜을 확인했다. 장비/주얼 탭 전환 중 하단 보유 목록 유지, 소켓별 장착 변경, 주얼 hover의 미니맵+옵션 표시와 경계 안 위치를 확인했다. 실제 PoB 계산·트리 데이터 연결 검증은 아니다.

수치 컨트롤 추가 지시: PoB처럼 값 입력칸 뒤에 + / − 버튼을 붙인다. 퀄리티·일반 소켓 S·주얼 소켓 J·옵션 수치·젬/캐릭터 레벨에 동일한 패턴을 사용하고 직접 숫자 입력도 유지한다. min/max/step은 실제 구현에서 엔진 메타데이터를 사용하며 경계에서 해당 버튼을 비활성화한다. 입력과 증감 버튼은 같은 자동 반영 경로를 사용한다.

## 계산 화면 고밀도·호버 근거 추가 지시

- 계산은 공격/방어 등의 배타적 카테고리 탭 뒤로 수치를 숨기지 않는다. 스킬 대상/Stat Set/계산 모드, 피해 유형 표, 시전/치명타/상태 이상과 능력치·요구량·생명력/마나/정신력/보호막·저항/방어/회피 등을 동시에 펼친 밀집 패널로 구성한다.
- 계산 탭에서는 전역 우측 요약의 같은 항목을 더 상세한 우측 계산 열에 통합해 중복 공간을 줄인다. 다른 탭의 상시 우측 요약은 유지한다.
- 각 결과값의 hover/focus에 기여값/유형/스킬 범위/적용 조건/출처 표를 제공한다. 기본값·추가·증가·증폭·최대값·점유·미적용을 구분하고 출처 합을 임의의 추천 점수로 해석하지 않는다.
- 필요한 경우 클릭 고정/닫기와 출처→장비/스킬/트리/조건 이동을 제공한다. 팝오버는 가장자리에서 위치를 보정하고 마우스를 표로 옮길 때 사라지지 않도록 한다.
- 정보 과밀집형에서도 최소 읽기 크기를 유지하고 패널 접기/검색을 제공한다. JSON을 결과/근거 화면으로 노출하지 않는다. 미적용은 0과 구분한다.
- 실제 구현은 원본 PoB Calcs/Breakdown이 제공한 항목·가용성·기여·조건·출처를 사용한다. 목업의 수치/기여 행은 가상 예시이며 실측 산출이나 게임 수식 구현이 아니다. 현재 입력과 이전 계산을 구분한다.

계산 목업 확인: 1920/1024에서 동시에 열린 밀집 패널·피해 유형 표·값 hover/focus 출처표·경계 보정·출처 이동·검색을 확인했다. 1024 피해 표의 열 너비로 항목명이 세로로 꺾이던 배치를 보정했다. 현재 목업은 계산 화면부터 열린다. 검증은 UI 시연이며 실제 PoB 산출 근거를 수집한 결과가 아니다.
