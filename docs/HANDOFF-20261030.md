# pok-ui 작업 인계 — 2026-10-30

## 가장 먼저 읽을 결정

사용자가 자리를 비우며 이 PC의 추가 구현을 중단하고 문서화·GitHub 푸시를 요청했다. 이번 인계는 구현 완료 선언이 아니다. **다음 작업의 우선순위는 아래 최종 요구이며, 과거 문서의 AI 우선 동선이나 두 저장소 동시 갱신 지시가 아니다.**

1. **pok-ui와 PoK는 각각 독립적으로 동작해야 한다.** pok-ui의 기본 사용에 PoK 설치·프로세스·연결·KB·AI를 필수로 두지 않는다. PoK의 독립 사용도 유지한다.
2. **먼저 PoB의 전체 사용자 작업을 pok-ui에서 수행할 수 있어야 한다.** AI 없이 직접 빌드를 열고 장비·스킬·트리·조건을 조작하고 계산을 확인하고 저장·복원하는 작업 공간을 우선한다. 화면에 메뉴가 있거나 XML을 보존한다는 것만으로 기능 동등성을 선언하지 않는다.
3. PoK를 통한 빌드 생성·자동 조작·추천은 그 이후의 선택 연동이다. AI 모델 요청 성공을 수동 편집기 완성의 선행 조건으로 삼지 않는다.
4. 연동할 때는 **양쪽이 실제 사용하는 PoB 버전/commit·출처의 일치/호환성**을 확인한다. 미연결과 버전 불일치를 구분한다. 연결 실패·PoK 종료가 독립 편집기의 수동 작업을 막지 않는 것이 목표다. 불일치를 숨기거나 한쪽을 자동 갱신하지 않고 계산 결과의 입력 revision과 버전 근거를 보존한다.
5. 독립 PoB 백엔드의 소유·배포·공유 방식/API는 **미결정·미구현**이다. 이 요구를 renderer에 게임 규칙/Lua/계산기를 복제하라는 뜻으로 해석하지 않는다. 기존 경계와 충돌하는 구조는 별도 설계하고, 엔진 저장소를 동시에 수정하지 않는다.

## 다른 PC에서 재개

새 폴더라면 다음처럼 UI만 받는다. 경로는 해당 PC에서 선택한다.

```powershell
git clone --branch skerfolg/coho https://github.com/skerfolg/pok-ui.git <new-ui-folder>
Set-Location <new-ui-folder>
git status --short --branch
git log -2 --oneline
npm ci
npm run check
npm run build
```

이미 UI checkout이 있다면 먼저 `git status`로 사용자 변경을 확인하고 보존한다. UI 원격을 fetch한 다음 작업 브랜치에서 fast-forward 가능한 경우만 갱신한다. reset/clean으로 기존 작업을 지우지 않는다. 엔진 저장소를 함께 checkout/pull하라는 지시가 아니다.

Node 요구/일반 명령은 [README](../README.md)를 따르되, 현행 `npm start`/`npm run dev`는 엔진 자동 연결을 시도하는 **기존 구현**이라는 점에 주의한다. `npm ci`/check/build 성공으로 runtime 리소스가 준비되는 것은 아니다. fresh clone의 native catalog/tree/runtime는 생성물이 빠져 있어 별도 준비 전 ready가 아니다. 기준 엔진에는 exporter가 없으므로 `bundle:prepare-checkout`를 그대로 실행하면 해결된다고 안내하지 않는다. 현행 생성 절차는 [DATA-BUNDLE.md](DATA-BUNDLE.md)에 있으나, 다음 독립 실행 설계의 정답으로 고정하지 않는다.

API/기존 native 회귀를 재현할 경우에만 **공유 엔진과 분리된 고정 clone** 및 의존성이 준비된 Python을 사용한다. native 검사는 해당 검사에 맞는 검증된 표시 리소스가 필요하다. 이전 dirty bundle을 최신 호환물인 것처럼 재생성하거나 검사 우회로 준비하지 않는다.

```powershell
$env:POK_SMOKE_ENGINE_ROOT = '<isolated-pinned-engine>'
$env:POK_SMOKE_PYTHON = '<prepared-python>'
node tests/engine-contract-smoke.cjs
# 표시 리소스와 Electron을 준비한 경우에만:
$env:POK_SMOKE_ELECTRON_EXECUTABLE = '<electron-executable>'
node tests/normalization-desktop-smoke.cjs
```

## 다음 세션의 첫 작업

1. AGENTS → 이 문서 → CURRENT-PLAN → ARCHITECTURE → DESIGN → VALIDATION 순서로 읽고 **목표/현재 구현/과거 검증**을 구분한다.
2. 기준 PoB의 실제 화면·코드·사용자 작업을 조사해 **기능별 대응표**를 만든다. 가져오기/캐릭터, 장비/제작/변형/룬/주얼/세트, 스킬/보조/모드/단계, 트리/전직/무기별 할당, 조건, 계산 상세/비교, 파티, 노트, 파일·빌드 관리를 조사 시작 범주로 삼되 전체 목록으로 단정하지 않는다.
3. 코드의 PoK 결합 지점을 감사한다: `src/main/index.ts`의 `verifiedContext`/`connectEngine`/계산·원문 생성 IPC, `src/main/game-data.ts`, `src/main/pok.ts`, `src/renderer/App.tsx`의 연결/카탈로그 gate. 독립 수동 작업을 막는 조건과 그 조건이 보호하는 출처 검증을 함께 기록한다.
4. 독립 PoB 기능/배포 계층과 선택 PoK 연동 계층을 설계한다. 게임 규칙 중복·임의 계산 구현·두 저장소 동시 변경 없이 책임과 필요한 API를 구체화한다. 기존 identity 검사를 무조건 삭제하는 것을 독립 실행 구현으로 삼지 않는다.
5. 수동 대표 동선부터 완료/검증한다: **PoK 미설치·미연결**에서 열기→편집→실제 PoB 계산→비교→저장/재시작→원본 PoB에서 재편집. 선택 연결의 버전 일치/불일치/엔진 종료는 그다음 검증한다.
6. PoK/AI 연동과 #188 품질 재평가는 이후 단계다. 이번 결과로 #188 해결을 선언하지 않는다.

참고 pob-ai는 기존 PoB 창/계산기를 활용하고 별도 패널·CLI를 연결하는 구조다. 전체 기능을 자체 UI로 다시 구현했다고 가정하지 않는다. 로컬 리뷰 사본/비교 보고서는 엔진의 `artifacts/reviews` 아래에 있었으며 이 UI 저장소에 복사하지 않았다. 다른 PC에서 자료가 없으면 공개 저장소의 검토 commit `5926042bc9db80df01481b99313769e8a57f66c4`를 별도 자료 폴더로 받아 확인할 수 있다.
