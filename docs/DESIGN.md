# 조작 안정성·일반 화면 정보 — 2026-11-06

유효한 숫자 조작마다 안내문/초안 버튼을 폼 위에 삽입하지 않는다. 같은 조작 대상의 위치·스크롤·숫자 폭을 유지한다. 생성 parser JSON, 카탈로그 raw metadata, 요약 리비전/시각, 해석/복원 건수, 미반영 옵션/계산 참고사항 목록은 일반 화면에 표시하지 않는다. 입력 오류와 실제 계산 실패는 간결하게 알리고, 원문/계산 기록의 보존 및 내부 revision 안전성은 유지한다.

# 제품 표현 원칙 — 2026-11-05

pok-ui는 PoB를 새로운 UI로 제공하는 제품이다. 일반 작업 화면에서 `원본 PoB`, 외부 연산을 대신 요청한다는 설명, 커밋/리비전 등의 구현 출처를 반복하지 않는다. 장착 비교·요구사항·계산 근거처럼 기능 자체의 이름을 사용한다. 이전 결과/갱신/실패 여부는 필요한 곳에서 짧게 표시하며, 버전·출처 검증과 기술 진단은 설정/고급 화면에 둔다. 원본 코드 참조는 https://github.com/PathOfBuildingCommunity/PathOfBuilding-PoE2.git 이며, 배포 계산은 검증된 고정 원본을 유지한다. 사용자 작업의 실제 반응 속도를 시각 수정에 우선한다.

# 사용자 시각 피드백 반영 — 2026-11-04

최신 장비 시각 기준: 사용자가 제공한 poe.ninja 그림처럼 실제 일러스트가 슬롯을 채우는 장착 개요를 사용한다. 무기/갑옷 등은 원래 장비 위치와 크기 비율로, 바알 신체 부위와 장착 주얼은 아래 썸네일 모음으로 구분한다. 양쪽 무기 위에 연동된 I/II 스위치를 두며 장착 가능 여부와 현재 값은 원본 PoB가 결정한다. 이미지 준비·출처/누락 fallback은 `ITEM-ARTWORK.md`를 따른다. 아래의 선 아이콘 기준은 빈 슬롯/이미지가 없는 경우의 fallback이다.

후속 확정: 일반 카드/hover는 원본 PoB가 현재 variant/range에서 포맷한 실제 옵션만 표시한다. `{range:…}` 등 원문을 필터링해 옵션인 것처럼 노출하지 않는다. 원문 아코디언은 사용하지 않고 카드의 `편집`으로 별도 창에서 확인/수정/적용한다. 적용은 작업 빌드 변경이며 파일 저장은 상단 `저장`이다. 일반 옵션과 지도 노드 클릭/Enter·능력치/주얼 선택은 별도 적용/파일 저장 없이 즉시 원본 연산과 자동 계산으로 연결한다.

사용자가 실제 시험 화면을 보고 디자인이 투박하다고 지적했다. 기능/안전성 검사의 통과가 시각 완성도를 대신하지 않는다. 기존 목업의 차분한 녹색 강조와 화면 위계를 다시 적용한다.

- 캔버스·패널·내비게이션·선택 상태의 표면을 구분하고 공통 카드/입력/숫자 컨트롤의 간격·테두리·굵기를 통일한다.
- 비어 있는 장비 슬롯은 얕은 테두리와 슬롯 형태 아이콘으로 표현한다. 아이콘은 실제 아이템 아트가 아닌 슬롯 종류 표시다. 선택은 테두리로, 장착 유무는 실제 input data로 표시한다.
- 일반 item preview는 이름/종류/요구 레벨·품질 등 제공된 입력 속성/옵션을 우선하고 Crafted/Prefix/Suffix/Implicits 같은 저장 문법은 고급 원문에 보존한다. 계산값을 프런트에서 추정하거나 원문을 수정하지 않는다.
- 원본 옵션의 Prefix/Suffix·socket/quality/roll 라벨은 사용자 표시명으로 정리하고 callback ID와 원본 값은 유지한다. revision/hash 같은 진단 출처는 고급 disclosure로 이동한다.
- 아이템 생성과 옵션 편집은 옵션당 한 행을 사용한다. 접두/접미의 이름·선택·슬라이더·직접 수치/+−를 같은 행의 공통 열에 정렬한다. 선택하지 않은 옵션도 수치 열을 비워 두어 선택 상자 폭을 유지한다. 퀄리티·소켓 등 단일 옵션도 한 행씩 배치한다.
- 1024에서 기본 메뉴는 한 줄로 유지하고 작은 슬롯은 구분 가능한 짧은 표시명을 쓴다. 접근성 이름과 tooltip은 전체 슬롯 이름을 유지한다. 작은 슬롯에 큰 아이콘을 넣어 문구가 잘리지 않게 한다.
- `workspace-polish.css`는 표현 계층이며 데이터/저장/undo/native 계산을 바꾸지 않는다. 1920/1024의 로드가 끝난 실제 폼을 확인한다.

# 1차 디자인 — 2026-10-05

사용자 지시로 현재 디자인을 1차 기준으로 삼고 구현을 시작했다. 이후 디자인 변경은 데이터·엔진 계약과 분리해 진행한다.

- Codex/Claude 데스크톱 앱과 유사한 차분한 단색 shell. 게임 희귀도 색상은 장비 텍스트에 제한한다.
- 좌측에 6개 메뉴와 최근 대화 목록. 대화 목록에서 이름 변경·고정·삭제를 수행한다.
- 상단은 빌드 선택/가져오기/내보내기/되돌리기/계산. 큰 히어로나 소개 카드를 넣지 않는다.
- 장비 화면은 장착 슬롯 목록 + **선택 장비와 저장 아이템 2열** + 우측 능력치 요약.
- 1920×1080 기본 검증, 1024×768에서도 2열과 능력치 요약을 유지한다. 전체 페이지 대신 패널 내부가 스크롤된다.
- 공격/자원/방어/저항/능력치 5개 그룹은 기본 펼침. 전체 통계와 진단은 별도 화면으로 확장한다.
- XML 저장 시점 값과 현재 편집본의 새 계산값을 출처 선택과 리비전으로 구분한다.
- 폼은 최소한의 여백과 구분선으로 정리한다. 기본 정보 밀도는 compact이며 설정에서 comfortable로 바꿀 수 있다.
- 패시브트리는 POK가 고정한 PoB 원본의 실제 좌표·연결만 사용한다. 데이터를 아직 받지 않았으면 가져오기 동작을 제공한다.

`tokens.css`에서 전역 색상·폭·높이·밀도, `layout.css`에서 구조, `components.css`에서 시각 표현을 수정한다. 게임 데이터, 파일 경로, 모델 호출을 CSS나 화면 mock 데이터에 넣지 않는다.

## 데스크톱 채팅 보완 (2026-10-08)

앱 테마 제목 표시줄은 드래그 영역과 운영체제 창 버튼을 유지한다. 기본 Electron 메뉴는 숨긴다. 입력창에는 모델·추론 강도·이미지 첨부와 실행 중 중지를 배치한다. 질문은 대화 안의 선택 카드로 표시하며 직접 답변도 받는다. 1024×768에서는 질문이 있는 영역을 스크롤해 선택지와 전송 버튼에 접근할 수 있어야 한다. 시간은 새 응답의 완료 시각과 총 소요 시간을 표시하고 첫 토큰 지연은 툴팁에 제공한다.
